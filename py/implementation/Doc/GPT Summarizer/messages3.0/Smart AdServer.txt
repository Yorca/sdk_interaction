    <h2 id="gpp"><a href="https://documentation.smartadserver.com/displaySDK/privacy.html#gpp">Global Privacy Platform (GPP)</a></h2>
    <p>The Global Privacy Platform (GPP) is an IAB specification helping all stakeholders in digital advertising to support regional privacy regulations more easily.
      GPP streamlines the transmission of privacy and consent signals from sites and apps across jurisdictions to ad tech providers. You will find more information in our <a href="https://help.smartadserver.com/s/article/Global-Privacy-Platform-GPP" target="_blank">Help Center</a>.</p>
    <p></p>
    <p>Since v7.21.0, the <strong>Smart Display SDK</strong> handles both TCFEU2 and USP1 frameworks via GPP, and rely on them to handle User ID sharing and location retrieval. You will find more information below.</p>
    <div markdown="span" class="alert alert-info" role="alert">
      <em class="fa fa-info-circle"></em> Despite <strong>Smart Display SDK</strong> compliancy with GPP, it is still compatible with the older TCFv2 and CCPA frameworks, outside GPP. Note that, for ID sharing and Location retrieval, GPP will have priority. 
        The <strong>Smart Display SDK</strong> will fallback on older TCv2 and CCPA frameworks only if there is no GPP string available, or if the CMP implementation is broken.
    </div>
    
    <h3 id="gpp-cmp"><a href="https://documentation.smartadserver.com/displaySDK/privacy.html#gpp-cmp">Consent Management Provider (CMP)</a></h3>
    <p>The first step to apply any consent framework handled by GPP is to collect the user's consent about the use of his personal data.</p>
    <p>This can be done through a <em>Consent Management Provider</em> (CMP). A CMP is a technology interface (usually an SDK for Apps environment) permitting
      apps developers to provide transparency and obtain consent where necessary for themselves and/or on behalf of their
      chosen third parties and to transmit informations about which vendors and which purposes a user has consented to
      with vendors.</p>
    <p>We recommend you integrate any CMP of your choice <strong>as long as it is compliant with IAB's framework</strong> and specifications since <strong>Smart Display SDK</strong> will retrieve consent based on these specifications:</p>
    <div class="row">
      <div class="col-md-3">
      </div>
      <div class="col-md-6">
        <a href="https://github.com/InteractiveAdvertisingBureau/Global-Privacy-Platform/blob/main/Core/CMP%20API%20Specification.md" target="_blank">
          <button type="button" class="btn btn-xl btn-success col-md-12" style="background:#62A8EA">IAB In-App Reference CMP for GPP</button>
        </a>
      </div>
      <div class="col-md-3">
      </div>
    </div>

    <h3 id="gpp-ids"><a href="https://documentation.smartadserver.com/displaySDK/privacy.html#gpp-ids">User and App Identifiers</a></h3>
    <p>As we are doing with TCFv2 compliancy since <strong>Smart Display SDK</strong> 7.15.0, some identifiers wonât be sent in the ad call when
      Smart is not given the userâs consent retrieved by GPP. The identifiers are the UID, the IFA, the IFV, and the DNTID. This happens if any of the juridiction handled under GPP do not give the consent.
      As the <strong>Smart Display SDK</strong> currently handles TCFEU2 and USP1 via GPP, if any of those reject the consent, the identifiers won't be sent.</p>

    <h3 id="gpp-location"><a href="https://documentation.smartadserver.com/displaySDK/privacy.html#gpp-location">Location retrieval</a></h3>
    <p>Since <strong>Smart Display SDK</strong> 7.21.0, the location is not sent in the ad call when Smart is not given the user's consent retrieved by GPP. This happens if any of the juridiction handled under GPP do not give the consent.
      As the <strong>Smart Display SDK</strong> currently handles TCFEU2 and USP1 via GPP, if any of those reject the consent, the identifiers won't be sent.</p>
    <p>You will find more information about automatic location retrieval <a href="https://documentation.smartadserver.com/displaySDK/privacy.html#automaticlocation">here</a>.</p>

    <h2 id="gdpr"><a href="https://documentation.smartadserver.com/displaySDK/privacy.html#gdpr">TCFv2 (GDPR EU)</a></h2>
    <p>Under the GDPR, you must make certain disclosures to your users in the <em>European Economic Area</em> (EEA) and obtain
      their consent to use, where legally required, their personal data (such as AdID) to serve ads or process some analytics.</p>
    <p><strong><a href="https://www.iab.com/" target="_blank">Interactive Adverstising Bureau (IAB)</a></strong> provides some tools to help you in this process.
      You might want to read more about how GDPR applies for advertising on <a href="https://iabeurope.eu/transparency-consent-framework/" target="_blank">iabeurope.eu/transparency-consent-framework</a>.</p>

      <h3 id="consent-management-provider"><a href="https://documentation.smartadserver.com/displaySDK/privacy.html#consent-management-provider">Consent Management Provider (CMP)</a></h3>
        <p>Like for <a href="https://documentation.smartadserver.com/displaySDK/privacy.html#gpp-cmp">GPP CMP</a>, we recommend you integrate any CMP of your choice <strong>as long as it is compliant with IAB's framework</strong> 
          and specifications since <strong>Smart Display SDK</strong> will retrieve consent based on these specifications:</p>

        <h3 id="gdpr-passing-user-consent"><a href="https://documentation.smartadserver.com/displaySDK/privacy.html#gdpr-passing-user-consent">Passing user's consent to <strong>Smart Display SDK</strong></a></h3>
          <p>Since the in-app environment is cookie-less, the TCF specifies the userâs shared preferences as the storage location for CMP data.
            From there, <strong>Smart Display SDK</strong> retrieves the consent signals and pass them to the ad request.
            The GDPR consent string have to be stored in the <code>SharedPreferences</code> on Android and in the
            <code>NSUserDefaults</code> on iOS, both by using the key <code>IABTCF_TCString</code>. Our SDK will get the consent string directly from the
            <code>SharedPreferences</code>/<code>NSUserDefaults</code> with the official IAB key.</p>

          <p>By using a CMP (compliant with the IAB specifications) you will have nothing to do. On the other hand, if you are
            using any other CMP that do not respect the IAB specifications, you will have to set the consent string in the
            <code>SharedPreferences</code>/<code>NSUserDefaults</code> manually.</p>

            <h2 id="ccpa"><a href="https://documentation.smartadserver.com/displaySDK/privacy.html#ccpa">CCPA (California)</a></h2>
            <p>
              The <em>California Consumer Privacy Act</em> (CCPA) is a privacy law applying to all residents of California (United
              States). It has been voted in 2018 and became effective in January 2020.
            </p>
            <p>
              You can find more information about this law and how to comply with it
              <a href="https://www.iab.com/guidelines/ccpa-framework/">in the dedicated IAB website</a>.
            </p>
            <p>As for GDPR, the IAB CCPA framework defines a consent string that will be obtained by a CMP and forwarded to
              all third parties by the SDK.</p>

            <h3 id="ccpa-passing-user-consent"><a href="https://documentation.smartadserver.com/displaySDK/privacy.html#ccpa-passing-user-consent">Passing CCPA consent string to <strong>Smart Display SDK</strong></a></h3>
              <p>
                The CCPA consent string have to be stored in the
                <code>SharedPreferences</code> on Android and in the
                <code>NSUserDefaults</code> on iOS, both by using the key
                <code>IABUSPrivacy_String</code>. Our SDK will get the consent string directly from the
                <code>SharedPreferences</code>/
                <code>NSUserDefaults</code> with the official IAB key.
              </p>
              <p>By using a CMP (compliant with the IAB specifications) you will have nothing to do. On the other hand, if you
                are using any other CMP that do not respect the IAB specifications, you will have to set the consent string
                in the
                <code>SharedPreferences</code>/
                <code>NSUserDefaults</code> manually.</p>
