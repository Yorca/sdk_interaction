<h1>Prerequisites</h1>
<ul>
<li><a href="https://www.pollfish.com/dashboard/dev/" target="_blank">Prodege Publisher Account</a></li>
<li>Android API 21 or later</li>
<li>Java 1.8</li>
<li>Kotlin 1.9.0</li>
</ul>
<p><br></p>
<h1>Quick Guide</h1>
<ol>
<li>Obtain a <a href="https://www.pollfish.com/signup/publisher" target="_blank">Publisher Account</a></li>
<li>Create a new App and copy the given API key</li>
<li>Create a new placement and copy the given placement id</li>
<li>Add Prodege SDK in your project</li>
<li>Initialize Prodge SDK</li>
<li>Load a Placement</li>
<li>Show the placement</li>
<li>Update you privacy policy and publish your app</li>
<li>Request your account to get verified</li>
</ol>
<p><br></p>
<blockquote>
<p><strong>Note:</strong> Apps designed for <a href="https://play.google.com/about/families/ads-monetization/" target="_blank">Children and Families program</a> should not be using Prodege SDK, since Prodege does not collect responses from users less than 16 years old.</p>
</blockquote>
<p><br></p>
<blockquote>
<p><strong>Note:</strong> Prodege SDK requires minSdk 21. If your app supports a lower minSdk you can still build your app please refer to section 7.</p>
</blockquote>
<h1>Analytical steps</h1>
<h2>1. Obtain a Publisher Account</h2>
<p>Register as a Publisher at <a href="https://www.pollfish.com/signup/publisher" target="_blank">www.pollfish.com</a></p>
<p><br></p>
<h2>2. Create a new App and copy the given API key</h2>
<p>Login at <a href="https://www.pollfish.com/docs/www.pollfish.com/login/publisher" target="_blank">www.pollfish.com</a> and click "Add a new app" on the <a href="https://www.pollfish.com/dashboard/dev/" target="_blank">Publisher Dashboard</a>. Copy then the given API key for this app in order to use later on, when initializing Prodege SDK within your code.</p>
<p><br></p>
<h2>3. Create a new placement and copy the given placement id</h2>
<p>Navigate in your <a href="https://www.pollfish.com/dashboard/dev/" target="_blank">Publisher Dashboard</a> under App Settings - Placements and choose "Create a Placement". You can select a Rewarded Ad or an Offerwall approach based on your placement needs with any of the available Ad Formats(it can change later through placement settings). Hit "Create Placement" and copy the generated Placement id in order to use later on.</p>
<p><br></p>
<h2>4. Add Prodege SDK in your project</h2>
<h3><strong>4.1. Retrieve Prodege Android SDK through maven</strong></h3>
<p>Retrieve Prodege SDK through <strong>maven()</strong> with gradle by adding the following line in your app's module <strong>build.gradle</strong> file:</p>
<pre><code class="language-groovy hljs">dependencies {
    implementation <span class="hljs-string">'com.prodege:prodege:7.0.0-beta07'</span>
}
</code></pre>
<p><br></p>
<h3><strong>4.2. Manual installation</strong></h3>
<blockquote>
<p><strong>Note:</strong> If you are using Android Studio, right click on your project and select New Module. Then select Import .JAR or .aar Package option and from the file browser locate the <code>.aar</code> file. Right click again on your project and in the Module Dependencies tab choose to add the module that you recently added, as a dependency.</p>
</blockquote>
<h3>4.2.1 Download Prodege Android SDK <code>.aar</code> file and import it into your project's libraries</h3>
<p>Click <a href="https://storage.googleapis.com/pollfish_production/sdk/Android/Prodege%20Android%20SDK-7.0.0-beta07.zip" target="_blank">here</a> to download the latest version of Prodege SDK.</p>
<p><strong>For Java based projects</strong> you will have to include the Kotlin runtime library in your module dependencies and set the java to version 1.8.</p>
<pre><code class="language-groovy hljs">android {
    <span class="hljs-comment">// ...</span>
    
    compileOptions {
        sourceCompatibility JavaVersion.VERSION_1_8
        targetCompatibility JavaVersion.VERSION_1_8
    }
}

dependencies {
    <span class="hljs-comment">// ...</span>
    
    implemetation <span class="hljs-string">'org.jetbrains.kotlin:kotlin-stdlib:1.9.0'</span>
}
</code></pre>
<blockquote>
<p><strong>Note:</strong> Skipping this step will result to runtime exception during the SDK initialization.</p>
</blockquote>
<p><br></p>
<h3>4.2.2 Add Google Play Advertising Identifier library to your project (Optional)</h3>
<p>Applications that integrate Prodege SDK may use Google Play Services library in order to give access to the Advertising ID of a device to the SDK. Further details regarding integration with the Google Play services library can be found <a href="https://developers.google.com/android/guides/setup" target="_blank">here</a>. By skipping this step you have to provide a userId during initialization. Refer to section 6 for more details.</p>
<pre><code class="language-groovy hljs">dependencies {
    implementation <span class="hljs-string">'com.google.android.gms:play-services-ads-identifier:18.0.1'</span>
}
</code></pre>
<p><br></p>
<h3><strong>4.3. Add Advertising Id permission for Android 12+ (Optional if manual installation without Google Play Advertising Identifier library integration)</strong></h3>
<p>Apps updating their target API level to 31 (Android 12) or higher will need to declare a Google Play services normal permission in the AndroidManifest.xml file.</p>
<pre><code class="language-xml hljs"><span class="hljs-tag">&lt;<span class="hljs-title">uses-permission</span> <span class="hljs-attribute">android:name</span>=<span class="hljs-value">"com.google.android.gms.permission.AD_ID"</span> /&gt;</span>
</code></pre>
<p>You can read more about Google Advertising ID changes <a href="https://support.google.com/googleplay/android-developer/answer/6048248" target="_blank">here</a>.</p>
<p><br></p>
<h3><strong>4.4. Add support for cleartext http traffic (Optional)</strong></h3>
<p>If you are looking to use Prodege Mediation surveys from all the providers, in order to avoid any faulty behaviour on new Android devices we would advice that you allow cleartext http traffic for the following domains. To achieve that you need to:</p>
<ol>
<li><p>Donwload <a href="https://raw.githubusercontent.com/pollfish/android-sdk-pollfish/b94e812c8b61ad1ac72c16cd63892168c892a04c/resources/domain_whitelist.xml" download="" target="_blank">
this file
</a> and place it under <strong><code>res/xml</code></strong> directory.</p></li>
<li><p>In your AndroidManifest.xml file add <strong><code>android:networkSecurityConfig</code></strong> tag as below:</p></li>
</ol>
<pre><code class="language-xml hljs"> <span class="hljs-tag">&lt;<span class="hljs-title">application</span>
    <span class="hljs-attribute">...</span>
    <span class="hljs-attribute">android:networkSecurityConfig</span>=<span class="hljs-value">"@xml/domain_whitelist"</span>&gt;</span>
</code></pre>
<p><br></p>
<h2>5. Initialize Prodege SDK</h2>
<p>In order to initialize Prodege SDK, you will need a <code>Context</code> and the api key as provided by the <a href="https://www.pollfish.com/dashboard/dev/" target="_blank">Publisher Dashboard</a> in step 2. We advise to call <code>Prodge.initialize</code> as soon as possible within your application's lifecycle, for example in the <code>onCreate()</code> mehod of your <code>Application</code> or <code>Activity</code> class. This will initialize Prodege SDK with default configuration. Read further for additional configuration options and notfications on the initialization result.</p>
<p><span style="text-decoration: underline">Kotlin:</span></p>
<pre><code class="language-kotlin hljs">Prodege.initialize(context, <span class="hljs-string">"API_KEY"</span>)
</code></pre>
<p><span style="text-decoration: underline">Java:</span></p>
<pre><code class="language-java hljs">Prodege.initialize(context, <span class="hljs-string">"API_KEY"</span>, <span class="hljs-keyword">null</span>, <span class="hljs-keyword">null</span>);
</code></pre>
<p><br></p>
<h3><strong>5.1. Configure Prodege SDK initialization (Optional)</strong></h3>
<p>You can use any of the additional configuration options to control the behaviour of the Prodege SDK by creating an <code>InitOptions.Builder</code> instance and build upon it.</p>
<p><span style="text-decoration: underline">Kotlin:</span></p>
<pre><code class="language-kotlin hljs"><span class="hljs-keyword">import</span> com.prodege.builder.InitOptions

<span class="hljs-variable"><span class="hljs-keyword">val</span> optionsBuilder</span> = InitOptions.Builder()
</code></pre>
<p><span style="text-decoration: underline">Java:</span></p>
<pre><code class="language-java hljs"><span class="hljs-keyword">import</span> com.prodege.builder.InitOptions;

InitOptions.Builder optionsBuilder = <span class="hljs-keyword">new</span> InitOptions.Builder();
</code></pre>
<p>Below you can see all the available options.</p>
<table>
<thead>
<tr><th>No</th><th>Option</th></tr>
</thead>
<tbody>
<tr><td>5.1.1</td><td><strong><code>.userId(String)</code></strong> <br> A unique identifier used to identify a user.</td></tr>
<tr><td>5.1.2</td><td><strong><code>.testMode(Boolean)</code></strong> <br> Toggle Prodege SDK test mode.</td></tr>
<tr><td>5.1.3</td><td><strong><code>.userProperties(UserProperties)</code></strong> <br> Provides user attributes upfront during initialization (only relevant with surveys).</td></tr>
<tr><td>5.1.4</td><td><strong><code>.advertisingOptOut(Boolean)</code></strong> <br> Opts out from the use of the device's advertising identifier.</td></tr>
</tbody>
</table>
<p><br></p>
<h3>5.1.1. <code>.userId(String)</code></h3>
<p>A unique identifier used to identify a user.</p>
<p>Setting the <code>userId</code> will override the default behaviour and use that instead of the Advertising Id in order to identify a user.</p>
<blockquote>
<p><strong>Note:</strong> <span style="color: red">You can pass the id of a user as identified on your system. Prodege will use this id to identify the user across sessions instead of an ad id/idfa as advised by the stores. You are solely responsible for aligning with store regulations by providing this id and getting relevant consent by the user when necessary. Prodege takes no responsibility for the usage of this id. In any request from your users on resetting/deleting this id and/or profile created, you should be solely liable for those requests.</span></p>
</blockquote>
<p><span style="text-decoration: underline">Kotlin:</span></p>
<pre><code class="language-kotlin hljs">optionsBuilder.userId(<span class="hljs-string">"USER_ID"</span>)
</code></pre>
<p><span style="text-decoration: underline">Java:</span></p>
<pre><code class="language-java hljs">optionsBuilder.userId(<span class="hljs-string">"USER_ID"</span>);
</code></pre>
<blockquote>
<p><strong>Note:</strong> Failing to provide a user identifier and missing Google Play Advertising Identifier library will result to a failed initialization, unless you explicitly request for advertising opt out (section 5.1.4).</p>
</blockquote>
<p><br></p>
<h3>5.1.2. <code>.testMode(Boolean)</code></h3>
<p>Toggles the Prodege SDK Test mode.</p>
<ul>
<li><strong><code>true</code></strong> is used to show to the developer how Prodege ads will be shown through an app (useful during development and testing).</li>
<li><strong><code>false</code></strong> is the mode to be used for a released app in any app store (start receiving paid surveys).</li>
</ul>
<blockquote>
<p><strong>Note:</strong> You should not be testing in live mode since your account can get banned automatically from the system.</p>
</blockquote>
<p>Prodege SDK runs by default in live mode. If you would like to test with test ads:</p>
<p><span style="text-decoration:underline">Kotlin:</span></p>
<pre><code class="language-kotlin hljs">optionsBuilder.testMode(<span class="hljs-literal">true</span>)
</code></pre>
<p><span style="text-decoration:underline">Java:</span></p>
<pre><code class="language-java hljs">optionsBuilder.testMode(<span class="hljs-keyword">true</span>);
</code></pre>
<p><br></p>
<h3>5.1.3. <code>.userProperties(UserProperties)</code> (only relevant with surveys)</h3>
<p>Provides user attributes upfront during initialization in order to skip or shorten Demographic surveys.</p>
<p>If you know upfront some user attributes like gender, age, education and others you can pass them during initialization in order to shorten or skip entirely Pollfish Demographic surveys and archieve better fill rate and higher priced surveys.</p>
<blockquote>
<p><strong>Note:</strong> You need to contact live support on our website to request your account to be eligible for submitting demographic info through your app, otherwise values submitted will be ignored by default.</p>
</blockquote>
<blockquote>
<p><strong>Note:</strong> You can read more on demographic surveys along with a list with all the available options <a href="https://www.pollfish.com/docs/demographic-surveys" target="_blank">here</a>.</p>
</blockquote>
<p>An example of how you can create and pass a <code>UserProperties</code> object during initialization can be seen below:</p>
<p><br></p>

<h3>5.1.4 <code>.advertisingOptOut(Boolean)</code></h3>
<p>Opts out from the use of the device's advertising identifier.</p>
<p>You can explicitly request to opt out from the use of the device's advertising Id. This will configure Prodege SDK to use a unique session identifier for each session. In case you skipped the Google Play Advertising Identifier installation, you should set this option to <code>true</code> to avoid initialization failure.</p>
<p>Providing a user identifier (section 5.1.1) will ignore the dependency on the device advertising identifier and use that instead of a session identifier.</p>
<p>Prodege SDK runs by default in opt-in mode. If you would like to opt out:</p>
<p><span style="text-decoration:underline">Kotlin:</span></p>
<pre><code class="language-kotlin hljs">optionsBuilder.advertisingOptOut(<span class="hljs-literal">true</span>)
</code></pre>
<p><span style="text-decoration:underline">Java:</span></p>
<pre><code class="language-java hljs">optionsBuilder.advertisingOptOut(<span class="hljs-keyword">true</span>);
</code></pre>
<p><br></p>
<p>After configuring the <code>InitOptions.Builder</code> instance you can proceed with the build of the <code>InitOptions</code> object and Prodege SDK initialization.</p>
<p><span style="text-decoration:underline">Kotlin:</span></p>
<pre><code class="language-kotlin hljs"><span class="hljs-keyword">import</span> com.prodege.Prodege

<span class="hljs-variable"><span class="hljs-keyword">val</span> initOptions</span> = optionsBuilder.build()

</code></pre>

<h3>6.3.3. <code>.rewardInfo(RewardInfo)</code></h3>
<p>An object passing information regarding the reward settings, overriding the values as speciefied on the <a href="https://www.pollfish.com/dashboard/dev/" target="_blank">Publisher Dashboard</a>.</p>
<p>We strogly advise that you should use the <a href="https://www.pollfish.com/dashboard/dev/" target="_blank">Publisher Dashboard</a> to provide Reward Info if your use case does not require a dynamic value.</p>
<pre><code class="language-kotlin hljs">data <span class="hljs-class"><span class="hljs-keyword">class</span> <span class="hljs-title">RewardInfo</span></span>(
    <span class="hljs-variable"><span class="hljs-keyword">val</span> points</span>: String,
    <span class="hljs-variable"><span class="hljs-keyword">val</span> conversionRate</span>: <span class="hljs-typename">Double</span>,
    <span class="hljs-variable"><span class="hljs-keyword">val</span> signature</span>: String
)
</code></pre>
<p><br></p>
<table>
<thead>
<tr><th>Field</th><th>Description</th></tr>
</thead>
<tbody>
<tr><td><strong><code>rewardName</code></strong></td><td>Overrides the reward name as specified in the <a href="https://www.pollfish.com/dashboard/dev/" target="_blank">Publisher Dashboard</a>.</td></tr>
<tr><td><strong><code>rewardConversion</code></strong></td><td>Overrides the reward conversion as specified on the <a href="https://www.pollfish.com/dashboard/dev/" target="_blank">Publisher Dashboard</a>. Conversion is expecting a number matching this function (<code>1 USD = X Points</code>) where <code>X</code> is a <code>Double</code> number.</td></tr>
<tr><td><strong><code>signature</code></strong></td><td>A parameter used to secure the <code>rewardName</code> and <code>rewardConversion</code>.</td></tr>
</tbody>
</table>
<p><br></p>
<p><code>signature</code> parameter is used to prevent tampering around reward conversion. The platform supports url validation by requiring a hash of the <code>rewardConversion</code>, <code>rewardName</code>, and <code>clickId</code>. Failure to pass validation will result in no ads.</p>
<p>In order to generate the <code>signature</code> field you should sign the combination of <code>${rewardConversion}${rewardName}${clickId}</code> parameters using the HMAC-SHA1 algorithm and your account's secret_key that can be retrieved from the Account Information section on your <a href="https://www.pollfish.com/dashboard/dev/" target="_blank">Publisher Dashboard</a>.</p>
<p><br></p>
<blockquote>
<p><strong>Note:</strong> Although <code>rewardConversion</code> and <code>rewardName</code> are mandatory for the hashing to work, <code>clickId</code> parameter is optional and you should add them for extra security.</p>
</blockquote>
<p><br></p>
<blockquote>
<p><strong>Note:</strong> Please keep in mind if your <code>rewardConversion</code> is a whole number, you have to calculate the signature useing the floating point value with 1 decimal point.</p>
</blockquote>
<p><br></p>
<p>Sample code to generate valid signatures</p>
<p><span style="text-decoration: underline">Kotlin:</span></p>
<pre><code class="language-kotlin hljs"><span class="hljs-keyword">import</span> java.util.*
<span class="hljs-keyword">import</span> javax.crypto.Mac
<span class="hljs-keyword">import</span> javax.crypto.spec.SecretKeySpec

<span class="hljs-variable"><span class="hljs-keyword">val</span> rewardConversion</span> = <span class="hljs-number">2.0</span>
<span class="hljs-variable"><span class="hljs-keyword">val</span> rewardName</span> = <span class="hljs-string">"Dollars"</span>
<span class="hljs-variable"><span class="hljs-keyword">val</span> clickId</span> = <span class="hljs-string">"CLICK_ID"</span>
<span class="hljs-variable"><span class="hljs-keyword">val</span> secretKey</span> = <span class="hljs-string">"ACCOUNT_SECRET_KEY"</span>

<span class="hljs-variable"><span class="hljs-keyword">val</span> valueToSign</span> = <span class="hljs-string">"$rewardConversion$rewardName$clickId"</span>

<span class="hljs-variable"><span class="hljs-keyword">val</span> signingKey</span> = SecretKeySpec(secretKey.toByteArray(Charsets.UTF_8), <span class="hljs-string">"HmacSHA1"</span>)
<span class="hljs-variable"><span class="hljs-keyword">val</span> mac</span> = Mac.getInstance(<span class="hljs-string">"HmacSHA1"</span>)
mac.init(secretKey)

<span class="hljs-variable"><span class="hljs-keyword">val</span> signature</span> = Base64.getEncoder().encodeToString(mac.doFinal(valueToSign.toByteArray(Charsets.UTF_8)))
</code></pre>
<p><span style="text-decoration: underline">Java:</span></p>
<pre><code class="language-java hljs"><span class="hljs-keyword">import</span> java.util.*;

Demographic surveys fire s2s callbacks with CPA=0. Publishers can provide rewards for users to incentivize them in completing the demographic surveys to get access to actual surveys.</p>
</blockquote>
<p>In our efforts to include publishers and be as transparent as possible we provide full control over the process. We let publishers decide if their users are served these standalone surveys or not, in 2 different ways. Firstly by monitoring the process in code and excluding any users by listening to the relevant noitifications and checking the Cost Per Action (CPA) field which will be 0 USD cents and also Survey Type which will be <code>Pollfish/Demographics</code>. Secondly, publishers can disable the Standalone Demographic surveys through the <a href="https://www.pollfish.com/dashboard/dev/" target="_blank">Publisher Dashboard</a> in the Settings area of an app. You can read more on demographic surveys <a href="https://www.pollfish.com/docs/demographic-surveys" target="_blank">here</a>.</p>
<p>If you know attributes about a user like gender, age and others, you can provide them during initialization as described in section 5.3.1.8 and skip or shorten this way, Pollfish Demographic surveys.</p>
